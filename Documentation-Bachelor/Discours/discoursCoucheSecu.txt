📌 CONTEXTE (15 secondes)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

"Maintenant, parlons sécurité.

CloudDiagnoze manipule des données sensibles : configurations d'infrastructure,
credentials AWS, informations d'entreprise.

La sécurité, ce n'est pas UN mécanisme, c'est une STRATÉGIE.

J'ai mis en place une approche de DÉFENSE EN PROFONDEUR : plusieurs couches
de protection qui se superposent. Si une couche est compromise, les autres
protègent toujours le système."


🎯 VUE D'ENSEMBLE (30 secondes)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[Montrer le diagramme complet]

"Ce diagramme représente les différentes couches de sécurité selon le modèle OSI.

Le modèle OSI, pour rappel, c'est une référence internationale qui décrit
comment les données circulent dans un réseau, en 7 couches.

Dans CloudDiagnoze, j'ai implémenté des protections sur 5 de ces couches,
plus une couche transversale pour la protection des données.

Chaque couleur représente une couche. Les blocs pleins sont ce qui est
implémenté. Les blocs en pointillés sont prévus pour la production.

Voyons chaque couche en détail."


🟣 COUCHE 7 - APPLICATION (1 minute)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[Pointer la bande violette en haut]

"La couche Application, c'est là où arrivent les requêtes HTTP.
C'est la première ligne de défense.

J'ai mis en place 4 mécanismes :

⚡ Rate Limiting
━━━━━━━━━━━━━━━━━
   C'est une protection contre les attaques brute-force.
   
   Concrètement : 5 tentatives d'inscription par minute maximum.
                  10 tentatives de connexion par minute maximum.
                  3 tentatives de reset de mot de passe par minute.
   
   Si quelqu'un essaie de deviner un mot de passe en faisant 1000 essais,
   il sera bloqué après 10.

🌐 CORS Policy
━━━━━━━━━━━━━━━
   Cross-Origin Resource Sharing.
   
   Ça contrôle QUELS sites peuvent appeler mon API.
   
   J'ai configuré ça via variables d'environnement : seuls les domaines
   autorisés peuvent faire des requêtes. Ça protège contre les attaques
   CSRF où un site malveillant essaierait d'utiliser mon API.

✅ Validation Pydantic
━━━━━━━━━━━━━━━━━━━━━━━
   Toutes les données entrantes sont VALIDÉES avant traitement.
   
   Email ? On vérifie que c'est bien un format d'email.
   Mot de passe ? Minimum 8 caractères.
   Provider ? Seulement 'aws' est accepté.
   
   Si les données sont mal formées, la requête est rejetée immédiatement.
   Ça protège contre les injections et les données malformées.

🛡️ Security Headers
━━━━━━━━━━━━━━━━━━━━
   Des en-têtes HTTP ajoutés par Nginx pour protéger contre :
   
   - X-Frame-Options : empêche qu'on mette mon site dans une iframe
     (protection clickjacking)
   - X-XSS-Protection : active la protection contre les scripts malveillants
   - X-Content-Type-Options : empêche le navigateur d'interpréter du code
     déguisé en autre chose

👉 Ces 4 mécanismes travaillent ENSEMBLE. Même si un attaquant passe le Rate
   Limiting, il doit encore passer la validation Pydantic, etc."


🔵 COUCHE 6 - PRÉSENTATION (45 secondes)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[Pointer la bande bleue]

"La couche Présentation gère le format et le chiffrement des données.

📦 Compression GZIP
━━━━━━━━━━━━━━━━━━━━
   Toutes les réponses HTTP sont compressées par Nginx.

   Ça réduit la bande passante et accélère le chargement.
   Mais surtout, ça rend plus difficile l'analyse du trafic par un attaquant.

🔐 HTTPS/TLS (Production)
━━━━━━━━━━━━━━━━━━━━━━━━━━
   En développement, on utilise HTTP pour simplifier.

   En production, HTTPS est indispensable. J'ai déjà préparé les certificats
   dans le dossier SSLkey/ et la config Nginx peut être adaptée en 5 minutes.

   HTTPS chiffre TOUT le trafic entre le navigateur et le serveur.
   Même si quelqu'un intercepte les données, il ne voit que du bruit.

👉 Le passage en HTTPS en production, c'est juste un changement de config Nginx.
   L'application est déjà prête."


🟢 COUCHE 5 - SESSION (1 minute)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[Pointer la bande verte]

"La couche Session gère l'authentification. C'est le CŒUR de la sécurité.

🎟️ JWT Tokens (HS256)
━━━━━━━━━━━━━━━━━━━━━━
   Quand un utilisateur se connecte, je lui donne un TOKEN JWT.

   Ce token contient son identité, cryptée avec une clé secrète (HS256).

   À chaque requête, le frontend envoie ce token. Le backend le vérifie.
   Si le token est modifié ou invalide, la requête est rejetée.

   Avantage : pas besoin de sessions côté serveur. C'est STATELESS.
   Le serveur ne stocke rien en mémoire. Ça permet de scaler facilement.

⏱️ Expiration 7 jours
━━━━━━━━━━━━━━━━━━━━━━
   Les tokens expirent automatiquement après 7 jours.

   C'est configurable via .env : on peut réduire à 1 heure pour plus de sécurité.

   Si quelqu'un vole un token, il n'est valide que 7 jours maximum.

🔑 Reset Token Sécurisé
━━━━━━━━━━━━━━━━━━━━━━━━
   Pour la réinitialisation de mot de passe, je génère un token aléatoire
   de 32 caractères avec la librairie secrets de Python.

   Ce token expire en 24 heures et n'est utilisable qu'UNE seule fois.

   Impossible à deviner : 256 bits d'entropie."


🟡 COUCHE 4 - TRANSPORT (30 secondes)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[Pointer la bande jaune/orange]

"La couche Transport, c'est TCP.

🔌 Connexions TCP
━━━━━━━━━━━━━━━━━
   Toutes les communications utilisent TCP, pas UDP.

   TCP garantit que les données arrivent dans l'ordre, sans perte.
   C'est fiable.

🔐 TLS 1.2/1.3 (Production)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   En production, on activerait TLS 1.3, le protocole de chiffrement le plus
   récent et le plus sécurisé.

   TLS 1.3 est 30% plus rapide que TLS 1.2 et corrige des vulnérabilités connues."


🔴 COUCHE 3 - RÉSEAU (45 secondes)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[Pointer la bande rouge]

"La couche Réseau, c'est l'isolation.

🐳 Isolation Docker Network
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   Docker crée un réseau PRIVÉ entre les containers.

   Le frontend (Nginx), le backend (FastAPI) et la base de données (MariaDB)
   sont dans un réseau isolé.

   Seuls les ports 80 (HTTP) et 8000 (API) sont exposés.

   La base de données n'est PAS accessible depuis l'extérieur.
   Un attaquant ne peut pas se connecter directement à MariaDB.

📡 Proxy Headers
━━━━━━━━━━━━━━━━
   Nginx transmet l'adresse IP réelle de l'utilisateur au backend.

   X-Real-IP et X-Forwarded-For permettent de tracer les vraies IPs
   même si on passe par un reverse proxy.

   Utile pour le Rate Limiting et les logs de sécurité."


🩷 SÉCURITÉ DES DONNÉES - Transversal (1 minute)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[Pointer la bande rose en bas]

"Et enfin, la protection des données. C'est TRANSVERSAL, ça traverse toutes
les couches.

🔒 Bcrypt Hashing
━━━━━━━━━━━━━━━━━━
   Les mots de passe ne sont JAMAIS stockés en clair.

   J'utilise bcrypt, un algorithme de hashing industriel.

   Bcrypt a 3 avantages :
   1. Il génère un SALT aléatoire à chaque fois (deux fois le même mot de
      passe donne deux hashs différents)
   2. Il est volontairement LENT (résiste au brute-force)
   3. Le facteur de coût est ajustable (plus les CPU deviennent puissants,
      on peut augmenter la difficulté)

✅ Validation Password
━━━━━━━━━━━━━━━━━━━━━━━
   Le mot de passe doit respecter des règles strictes :

   - Minimum 8 caractères
   - Au moins une majuscule
   - Au moins une minuscule
   - Au moins un chiffre

   Ça bloque les mots de passe faibles comme '123456' ou 'password'.

🔑 Variables d'Environnement
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   Tous les secrets sont dans des fichiers .env, pas dans le code.

   La clé JWT, les credentials de base de données, les origines CORS...
   Tout est externalisé.

   En production, ces variables viennent d'un gestionnaire de secrets
   (AWS Secrets Manager, Vault...), pas du code source.

👉 Même si quelqu'un accède à mon GitHub, il ne trouvera AUCUN secret.
   Les fichiers .env sont dans le .gitignore."


🎬 CONCLUSION (30 secondes)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

"En résumé, CloudDiagnoze implémente une DÉFENSE EN PROFONDEUR :

✅ Couche 7 : Rate Limiting, CORS, Validation, Security Headers
✅ Couche 6 : Compression GZIP (HTTPS prêt pour prod)
✅ Couche 5 : JWT avec expiration, tokens sécurisés
✅ Couche 4 : TCP fiable (TLS prêt pour prod)
✅ Couche 3 : Isolation Docker, Proxy Headers
✅ Données : Bcrypt, validation mots de passe, secrets externalisés

Même si une couche est compromise, les autres protègent le système.

C'est le principe de la DÉFENSE EN PROFONDEUR : ne jamais dépendre d'une
seule ligne de défense."

❓ ANTICIPER LES QUESTIONS DU JURY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: "Pourquoi pas HTTPS en développement ?"
R: "Pour simplifier le développement local. Docker et les certificats auto-signés
    compliquent le debug. Mais tout est prêt pour la prod : les certificats sont
    générés, la config Nginx est préparée."

Q: "Que se passe-t-il si quelqu'un vole un JWT ?"
R: "Le token expire après 7 jours. En production, on peut réduire à quelques heures
    et implémenter un système de refresh token. On peut aussi invalider tous les
    tokens en changeant la SECRET_KEY."

Q: "Bcrypt, c'est vraiment sécurisé ?"
R: "C'est l'algorithme recommandé par OWASP. Il est utilisé par GitHub, Dropbox,
    et la plupart des grandes entreprises. Sa lenteur volontaire le rend résistant
    au brute-force même avec des GPU puissants."

Q: "Comment vous gérez les attaques DDoS ?"
R: "Le Rate Limiting bloque les requêtes excessives. En production, on ajouterait
    un CDN comme Cloudflare qui absorbe les attaques avant qu'elles n'atteignent
    le serveur."

Q: "Les données sont-elles chiffrées en base ?"
R: "Les mots de passe sont hashés. Pour les autres données, le chiffrement
    at-rest dépend de l'hébergeur (AWS RDS le propose nativement). Mais les
    données en transit seront chiffrées par TLS en production."
