💡 RÈGLE D'OR : Moins tu lis, mieux c'est.

1. COMMENCE FORT
   → Pas de "Bonjour, je m'appelle..."
   → Commence par : "Imaginez gérer 50 instances EC2 à la main..."
   → Pose un PROBLÈME, puis donne ta SOLUTION

2. UN DIAGRAMME = UNE IDÉE
   → Ne dis pas TOUT ce qu'il y a sur le diagramme
   → Choisis 3-4 points clés par diagramme
   → Le reste, c'est pour les questions du jury

3. FAIS DES DÉMOS COURTES
   → Montre l'interface AVANT d'expliquer le code
   → "Regardez, je clique ici... et voilà ce qui se passe"
   → La démo PROUVE ce que tu dis

4. GÈRE TON TEMPS
   → 40 min de présentation, c'est LONG
   → Prévois 35 min de contenu (marge de sécurité)
   → Si tu finis tôt, c'est OK. Si tu débordées, c'est stressant.

5. ANTICIPE LES QUESTIONS TECHNIQUES
   → "Pourquoi FastAPI et pas Django ?"
   → "Pourquoi MariaDB et pas PostgreSQL ?"
   → "Comment tu gères les erreurs ?"
   → Les réponses sont dans tes discours, relis-les !
